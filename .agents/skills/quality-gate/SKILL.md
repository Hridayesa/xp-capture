# Quality gate

Проверяй результат пропорционально риску и не скрывай пропущенные проверки.

1. Прочитай активный OpenSpec change и составь матрицу requirement → evidence.
2. Запусти `bun run tools/verify.ts` из корня проекта. Если изменён только один изолированный компонент, сначала можно выполнить узкие проверки, но перед archive нужен полный набор.
3. Проверь изменённые внешние контракты отдельно: HTTP/Tauri error mapping, migrations, serialization и negative cases.
4. Просмотри diff на расширение scope, утечки секретов, `unwrap/expect` в fallible production paths и обход архитектурных границ.
5. Сообщи команды, фактические результаты и непройденные проверки с причиной. Отсутствующая команда или Docker — gap, а не успешная проверка.
6. Не архивируй change при failing gate, невыполненных задачах или существенном несоответствии спецификации.

Для PostgreSQL integration tests требуется доступный Docker daemon; тест должен запускать контейнер через testcontainers, применить production migrations и проверить хотя бы один отрицательный сценарий.
